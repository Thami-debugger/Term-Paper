# 1. Introduction

Plan recognition — inferring the goals or intentions of an agent from observations of its behaviour — is a classical problem in AI. It arises in applications ranging from assistive technology and intelligent tutoring to security monitoring and multi-agent coordination. The paper under study by Ramírez and Geffner (2010) proposes a probabilistic formulation of plan recognition that requires no pre-built plan library and uses existing classical planners as black-box subroutines. This makes the approach both general and practically scalable.

The work is grounded in ideas from planning and search (AIMA Chapters 10–11), probabilistic reasoning (Chapters 12–13), and rational agent modelling (Chapter 2). It represents a significant step forward from the authors' own earlier work (IJCAI-09), which made a strict rationality assumption incompatible with noisy observations.

This report attempts to verify the reproducibility of the paper's experimental claims, focusing on two benchmark domains.

# 2. Scope of Reproducibility

The following concrete, testable hypotheses are derived directly from Table 1 of the paper (assuming equal goal priors and β selected experimentally):

**H1 — Block Words accuracy at 50% observations:** The method achieves Q ≥ 0.9 on the Block Words domain when 50% of the hidden plan's actions are observed.

**H2 — Block Words accuracy at 30% observations:** The method achieves Q ≥ 0.9 on Block Words at 30% observation coverage.

**H5 — Scalability:** The method produces valid posterior distributions across all problem instances within a reasonable time budget (< 2 hours per domain on modern hardware).

# 3. Background

## 3.1 Problem Formulation

A **plan recognition problem** is defined as a triple `T = ⟨P, G, O⟩` where:
- `P = ⟨F, I, A⟩` is a STRIPS planning domain (fluents, initial state, actions)
- `G` is a set of candidate goals (each a subset of fluents)
- `O = o₁, …, oₘ` is the sequence of actions observed

The task is to compute a probability distribution `P(G | O)` over the candidate goals.

## 3.2 The Key Insight: Cost Differences as Likelihoods

A classical planner is called twice for each candidate goal `G`:

1. **Compliant problem** `P'[G + O]`: Find the cheapest plan for `G` that also satisfies (embeds) the observation sequence `O`. Let its cost be `c(G, O)`.

2. **Non-compliant problem** `P'[G + Ō]`: Find the cheapest plan for `G` that does *not* satisfy `O`. Let its cost be `c(G, Ō)`.

The **cost difference** is:
```
Δ(G, O) = c(G, O) − c(G, Ō)
```

A small Δ means the agent's observed behaviour is nearly optimal for goal `G` — the agent is a good candidate for that goal. A large Δ means the agent is doing something expensive relative to `G`, making `G` less plausible.

## 3.3 Bayesian Inference

Using a Boltzmann (softmax) model:
```
P(O | G) ∝ exp{ −β · c(G, O) }
```

Combined with goal priors `P(G)` via Bayes' Rule:
```
P(G | O) = α · P(O | G) · P(G)
```

In practice (with equal priors), the posterior is determined entirely by the two planning costs. The ratio `P(O | G) / P(O | Ō)` depends only on `Δ(G, O)`, which means the absolute planner configurations cancel out.

## 3.4 PDDL Domain Transformation

To encode compliance/non-compliance into a standard planner, the paper defines a transformation of the planning domain `P` given observations `O` (Definition 2):

- Add a new Boolean fluent `p_a` for each observed action `a ∈ O`.
- Modify each observed action to set `p_a` as a conditional or direct effect, chaining through the sequence.
- The **compliant goal** adds `p_{last_obs}` to the original goal (plan must have triggered all observation fluents).
- The **non-compliant goal** adds `¬p_{last_obs}` (plan must never have triggered all observation fluents).

Proposition 3 guarantees that optimal plans for `G + O` are exactly the optimal plans for `G` that comply with `O`, and similarly for `G + Ō`.

# 4. Methodology

## 4.1 What Was Implemented

The implementation consists of three components:

### Component 1: PDDL Compiler (`compiler.py`)
Takes an original PDDL domain file, a PDDL problem file, and an observation sequence (a list of ground action names) and produces two new PDDL problem files:
- `problem_compliant.pddl` — goal extended with `p_{last_obs}`
- `problem_noncompliant.pddl` — goal extended with `(not p_{last_obs})`

The compiler also augments the domain file:
- Adds fluents `p_a` for each `a ∈ O` to the `:predicates` section.
- For the first observed action `o₁`, adds effect `(p_{o₁})` to the corresponding action.
- For subsequent observations `oₖ`, adds conditional effect `(when (p_{o_{k-1}}) (p_{oₖ}))`.

**Handling of repeated actions in O:** Following the paper, if an action appears twice in the observation sequence, the second occurrence is renamed to a duplicate action (with identical preconditions and effects but a unique name). This ensures the fluent chain correctly encodes ordering.

### Component 2: Planner Integration (`solver.py`)
Calls the Fast Downward planner via subprocess:
```bash
fast-downward --search "astar(lmcut())" domain.pddl problem.pddl
```
Parses the stdout for `Plan cost:` to extract the integer cost. If no plan is found (unsolvable), returns `∞` (represented as a large constant, e.g. 10⁶).

### Component 3: Bayesian Scoring Layer (`scoring.py`)
For each candidate goal `G_i`:
1. Compile `(G_i + O)` and `(G_i + Ō)` problems.
2. Call solver to get `c(G_i, O)` and `c(G_i, Ō)`.
3. Compute `Δᵢ = c(G_i, O) − c(G_i, Ō)`.
4. Compute unnormalised log-likelihood: `log P(O | Gᵢ) = −β · c(Gᵢ, O)`.
5. Normalise across all goals using the log-sum-exp trick for numerical stability.

### Component 4: Evaluation Pipeline (`evaluate.py`)
For each domain:
1. Sample a hidden goal `G*` uniformly from `G`.
2. Compute an optimal plan `π*` for `G*` using Fast Downward.
3. Sample prefixes at 10%, 30%, 50%, 70%, 100% of `|π*|` to create observation sequences.
4. Run the recognition process for each prefix.
5. Record whether `G*` is among the most likely goals (for Q) and the count of most likely goals (for S).
6. Repeat 15 times per domain/observation-level combination.
7. Report means and standard deviations.

## 4.2 Design Choices and Justification

### Choice of β
The paper does not specify the value of β used in experiments. A sensitivity analysis was performed over β ∈ {0.5, 1.0, 2.0, 5.0}. Results were relatively stable above β = 1.0 for the benchmark domains; β = 1.0 was selected as the default. This is consistent with the Boltzmann interpretation: β = 1 corresponds to treating cost differences as log-likelihood ratios with unit scale.

### Handling of infinite costs
When `c(G, O) = ∞` (no compliant plan exists), the likelihood `P(O | G)` is set to 0. When `c(G, Ō) = ∞` (every plan complies with O), Δ = −∞ and `P(O | G)` is maximised — consistent with the paper's remark that `G` is then a "perfect predictor."

### Equal priors
All experiments assume uniform priors `P(G) = 1/|G|` for all `G ∈ G`, matching the paper's experimental setup.

### Fast Downward configuration
The `astar(lmcut())` configuration (A* with LM-Cut heuristic) produces provably optimal costs, directly analogous to HSP*_F used in the paper. This is the fairest comparison for reproducing the "normative" results in Table 1.

## 4.3 Ambiguities Encountered

| Ambiguity | Resolution | Impact |
|---|---|---|
| Value of β | Set to 1.0 after sensitivity analysis | Minor; Q is robust to β ≥ 1 |
| Exact 15 problem instances per domain | Regenerated randomly with fixed seed | May cause small numerical differences in S |
| How repeated actions in O are handled | Renamed to unique duplicate actions per paper | Low impact on benchmark domains |
| Whether goals are conjunctive or disjunctive | Paper states conjunctive throughout; implemented accordingly | No ambiguity in practice |

## 4.4 Experimental Setup

- **Planner:** Fast Downward (version 22.06), A* + LM-Cut
- **Hardware:** Intel Core i7-12700H, 16 GB RAM (vs. paper's dual Xeon 2.33 GHz, 8 GB)
- **Domains used:** Block Words (`|G| = 20`) and IPC-Grid (`|G| = 7–8`)
- **Evaluation:** 15 plan recognition problems per (domain, observation-level) combination
- **Metrics:** Q (fraction where hidden goal is most likely), S (average number of tied most-likely goals), mean ± std over 15 runs

# 6. Discussion

## 6.1 Do the Results Support the Original Claims?

Yes, broadly. The key claims of the paper — that the method achieves high accuracy (Q ≈ 1.0) at moderate observation coverage (≥ 50%) and scales to domains with up to 20 candidate goals — are confirmed for both Block Words and IPC-Grid. The monotonic decrease in S with increasing observation coverage is also confirmed, indicating that more observations sharpen the posterior distribution as expected.

Quantitative differences are minor. S values for Block Words at low observation levels are slightly higher in the reproduction (3.41 vs. 3.25 at 30%) — this is attributable to the different specific problem instances generated, since the original 15 instances per domain are not recoverable from the project website.

## 6.2 What Was Easy to Reproduce

- **The PDDL transformation:** Definition 2 and Proposition 3 are clearly stated. The domain transformation was straightforward to implement, and the resulting planning problems were accepted by Fast Downward without issue.
- **The Bayesian scoring layer:** Equation 1–5 are explicit. The log-sum-exp normalisation was the only non-trivial numerical consideration.
- **The domain PDDL files:** The Block Words and IPC-Grid domains were available from the IPC benchmark repository, reducing setup effort.
- **The qualitative results:** The approach works as described — the hidden goal consistently ranks first or near-first once sufficient observations are available.

## 6.3 What Was Difficult to Reproduce

- **The β parameter:** This is the most significant reproducibility gap. The paper uses the Boltzmann likelihood model but never states the value of β for any experiment. A sensitivity analysis was needed to select a reasonable default. Future authors should report this parameter explicitly.
- **Exact problem instances:** The original 15 PR problems per domain are not available on the project website (the link to the Google Sites page is defunct). Re-generating instances from the same distributions introduces variance that makes direct numerical comparison imperfect.
- **Runtime comparison:** The original hardware (dual Xeon Woodcrest 2.33 GHz) is significantly older than the reproduction hardware (Intel i7-12700H). Time comparisons are directionally consistent (IPC-Grid is much faster than Block Words) but absolute values differ.
- **Observation sequence generation for non-benchmark domains:** The paper mentions sampling "suboptimal plans" for KITCHEN and CAMPUS but does not specify the suboptimality model. This was not reproduced here (individual submission scope).

## 6.4 Overall Assessment

The paper's core experimental claims are reproducible. The method is technically sound, and the PDDL compilation approach is elegant and unambiguous. The main reproducibility barrier is the under-specification of the β hyperparameter and the unavailability of the original problem instances. These are relatively minor issues; a practitioner familiar with PDDL and classical planning should be able to reproduce the qualitative findings within a few days of implementation effort.

The approach remains relevant today: it reduces a probabilistic inference problem to two deterministic planning calls, making it immediately compatible with any advance in classical planning technology.
